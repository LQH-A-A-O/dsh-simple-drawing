# layered-art —— 用代码作画

**核心命题一：结构和配色可以分离。** 一张图一旦变成「多边形 + 内孔 + 颜色」的结构，
换配色就是换一张色阶表重跑（0.1 秒），改轮廓就是动几个控制点。

**核心命题二：分区（色块）和细节（像素）要分两个阶段做。**
分区只能给出"这一块蓝、那一块白"，而且分区是按「面」判定的 —— 边界只能沿三角面走，
**一定锯齿**。所有细节都在像素阶段补。

## 五条路线，按"你想画什么"选

| 路线 | 适合 | 核心模块 | 上限 |
|---|---|---|---|
| **A 描图重构** | 已有参考图，要改配色/轮廓 | `shapes` `render` `art.py` | 受参考图限制，能到 94~99% 相似 |
| **B 网格立绘** | 要原创角色、要人体比例正确 | `mhsource` `mesh` `build_char` `garment` `parts` `pixel` | 日漫平面着色立绘 |
| **C 方块角色** | 《我的世界》式方块人 | `mcblock` `mcplayer` `skin` | MC 皮肤风（含 64×64 逐面设计） |
| **D 像素画** | 任何平涂图 → 像素画 | `pixelart` | 只要输入是平涂色块就行 |
| **E 部件装配** | 五官/身体要**分别精修**再合成；要拼豆锯齿风 | `rig` `bead` `assembly` `templates` `composite` | 部件级细节，可到"每个像素都可看" |
| **F 渐进生长** | 要拼豆**图纸 + 买豆子清单**；要"每层都完整可看" | `bead_grow` `bead_palette` `bead_from_ref` | 每层独立可用，可按层交件 |
| **G 自适应四叉树** | 画布要多大有多大；平坦区省、细节区细 | `bead_quad` | 精细度只受参考图与误差阈值限制 |

### 路线 E 为什么值得单独列一条

A~D 都是**在一张画布上整体构图**，于是每个部位能分到多少像素由整图尺寸决定 ——
眼睛只占 6 格时，画得再细也没用。E 反过来：**一个部件一块画布，按自然尺寸画，
再按整数格偏移或头高坐标装配**。局部比例因此不会因为"地方太小"而走形。

关键合成点：**高分辨率是母版，拼豆是输出滤镜** —— 同一份母版能同时出精细版和拼豆版。

**B 和 C 的差别值得先想清楚：**

| | B 网格 | C 方块 |
|---|---|---|
| 轮廓 | 圆润，但边界沿三角面走 → 一定锯齿（靠 2D 掩膜平滑修） | 天然直角/阶梯，MC 味 |
| 粗细 | 几何锥度 + `slim_legs` 收腿 | **像素梯度**（几何可以等宽） |
| 面数 | 36972 | 252 |
| 五官 | 真实网格组件 | 几个薄片方块 |

# 路线 A：描图重构

## 快速上手

```bash
S=<本技能目录>
python $S/art.py extract ref.png -o spec.json          # 提取（会报告重建误差）
python $S/art.py info    spec.json --top 30            # 看区域清单
python $S/art.py restyle spec.json -o out/             # 7 套配色 + 联络图
python $S/art.py layers  spec.json -o layers.png       # 四层分解
python $S/art.py region  spec.json --x 300 --y 200     # 这一点落在哪块
python $S/art.py verify  spec.json ref.png             # 质量验收
```

代码里用：

```python
import sys; sys.path.insert(0, r'<本技能目录>')
import shapes as ST, render as R

sp = ST.extract('ref.png', k=12, eps=3.0)     # 结构
print(ST.stats(sp))                            # 区域/顶点/内孔
print(ST.verify(sp, 'ref.png'))                # 重建误差 + 吻合率

night = R.recolor(sp, R.PRESETS['夜色霓虹'])   # 换配色（几何不动）
img = R.render_layers(night, light=(-1,-1), band=6, outline=2)['final']
img.save('night.png')

sym = ST.mirror_half(sp)                       # 左右对称化
ST.transform_region(sp, 5, dx=8, scale=1.1)    # 动第 5 块
```

## 抽象度甜点（用一张 960×1282 的低多边形参考图测的）

| EPS | 块数 | 顶点数 | 重建误差 | 观感 |
|---|---|---|---|---|
| 1.2 | 518 | 11,958 | 3.78 | 接近原图 |
| **3.0** | **471** | **4,536** | **4.09** | **几乎无差别 ← 默认值** |
| 6.0 | 358 | 2,549 | 4.83 | 略棱角，仍很像 |
| 12.0 | 249 | 1,394 | 6.42 | 明显多边形，仍认得出 |
| 24.0 | 146 | 709 | 10.07 | 脸崩了，认不出 |

**62% 的顶点只承载 0.15/255 的信息** —— 真正的骨架就是 4,000~5,000 个顶点。
可辨识下限约 1,400 顶点。`k=12` 够用（色数越多块越碎，低多边形图本来色阶就少）。

⚠️ **这张表只有在 kmeans 种子固定之后才有意义。** 见下面「坑」里的
`cv2.setRNGSeed` —— 不设种子时同一张图连调三次会得到 475 / 464 / 453 块，
上面这些数字全部浮动。表里是 `KMEANS_SEED=20260928` 下的值。

# 路线 B：网格立绘

## 流程

```
MakeHuman npz（只读）
   ↓ mhsource.apply_targets        变形（体型配方）
   ↓ build_char.partition          七头身 canon 分成十块
   ↓ build_char.slim_legs          几何收腿
   ↓ mesh.render_regions           每块渲成色块（2D 掩膜平滑边界）
   ↓ garment.blouse/skirt/...      从人体生成适配的衣服壳
   ↓ parts（或自写组装）           按 Live2D 式层序合成
   ↓ pixel.apply_ops               像素级细修（五官、阴影、边缘）
   ↓ pixelart.pixelize             可选：转像素画
```

## 七头身 canon（`build_char.CANON7`）

从脚底 0 到头顶 1，单位 = 身高：

```
脚底 0.000  脚踝 0.043(0.3头)  膝 0.286(2头)  胯 0.500(3.5头)
腰 0.571(4头)  胸 0.643(4.5头)  肩 0.786(5.5头)  下巴 0.857(6头)  头顶 1.000
```

十块：`头 脖子 胸 腰 胯 大腿 小腿 脚 胳膊 手`（外加素体头发壳 = `头发`，用组件时要丢掉）。

实测边界都落在正确位置（膝 t=0.286 → 大腿/小腿交界、胯 0.500、肩 0.786、下巴 0.857）。

`build_char.colorize_blocks()` 能出一张**十块分块图**（每块一个明显不同的颜色），
用来核验 canon 切得对不对 —— **调参时先看这张图，别直接看成品**。

## 关键参数（都有实测出处）

| 参数 | 含义 | 实测值 |
|---|---|---|
| `W_NECK` | 脖子**半宽**（相对身高） | 0.035 → 脖子总宽 0.062 身高，脖子/头 ≈ 0.56 |
| `W_ARM` | 超过它算胳膊 | 0.105 |
| `slim_legs(k_center, k_*)` | 连轴线往中轴收 + 按腿轴收半宽 | 0.68 / 0.75 → 每条小腿 0.065 身高（真实 0.06~0.07） |
| `cel` / `cel_thr` | 日漫平涂阴影：暗面亮度 / N·L 阈值 | 0.76 / 0.08 |
| `shadow_smooth` / `shadow_edge` | 阴影形状的 2D 平滑与重二值化 | 1.0 / 4.0 |
| `render_regions(smooth, edge)` | 色块边界的掩膜平滑半径 / 陡峭度 | 躯干 5.0，头 3.0 |

# 路线 C：方块角色（《我的世界》式）

## 核心：粗细靠**像素梯度**，不靠几何

一个方块有 6 个面：**前后两个面不切**（正对相机，一个整色）；
**左右两个侧面各切成 N 条竖条**，每条一个亮度：

```python
RAMP = (0.74, 0.88, 1.00, 0.90, 0.78)     # 暗-亮-暗；条数取奇数让中间有最亮的一条
```

中间那条最亮、两侧渐暗 —— 一个纯方块因此读起来是根**圆柱**。
所以 `uniform_limbs=True` 时大腿/小腿**设成同一宽度**，粗细之分完全由梯度读出来。

```python
import mcblock as MB, mcplayer as MP, mesh as ME
V, F, C = MB.figure_boxes(PAL, h=15.279, uniform_limbs=True)   # False = 用解剖宽度
img = ME.render_regions(V, F, size, C, bg=BG,
                        shade=False,      # ⚠️ 亮度已经写在每个面的 rgb 里了
                        smooth=0.0, outline=None, margin=0.05)
```

**⚠️ `shade` 必须关掉。** 亮度已经写进 `rgb` 了，再叠一次光照会得到两套明暗打架的脏结果。

## 两套比例

| 比例 | 头占身高 | 出处 |
|---|---|---|
| **MC 4 头身** | 1/4 | `mcplayer.MC_BOX`：头 8×8×8、身 8×12×4、臂腿 4×12×4，总高 32 |
| **七头身** | 1/7 | `mcblock.CANON_BOX`：同 `build_char.CANON7` |

**⚠️ canon 里的半宽/半深是「相对身高」的比例，必须乘身高换成绝对长度。**
漏了这一步人物会被压成 1:56 的细条（实测小图变成 16×767）。

## 想做 MC 皮肤那种精度：在**小精灵分辨率上**落笔

参考图那种精度（发丝、眼睛、裙褶）本质是**贴在方块面上的像素贴图**。
做法：渲成大图 → `pixelart.pixelize` 到小精灵 → 用 `pixel.apply_ops` 在小精灵上画。

**在小精灵上画，不要在大图上画再缩小** —— 细节会被"每格取众数"吃掉。

**⚠️ 所有锚点用几何算，不要靠颜色找。** 我们本来就知道每块的 t 值：

```python
U = H / T_TOP                       # 1 单位身高 = 多少精灵像素
def y_of(t): return int(round((T_TOP - t) / T_TOP * H))
def x_of(u): return int(round(W / 2 + u * U))
```

MC 皮肤风的分辨率：**头只该有 8~16 格**（取 cell 让身高约 150 格）。

# 路线 D：像素画

```python
import pixelart as PA
big, small, pal = PA.pixelize(img, cell=10, bg=BG, outline=(38,36,46),
                              pad=2, max_colors=26, diag_outline=False)
```

| 步骤 | 做法 |
|---|---|
| 分格 | 按 cell×cell 分格，每格取**众数色** |
| 量化 | 全图收敛到固定调色板 |
| 描边 | 小图上前景外缘描一圈（**不环绕**） |
| 放大 | **NEAREST** 硬边放大 |

**两个做错了就不是像素画的点：**

1. **每格取众数，不能取平均。** 平均会造出一堆中间色，出来是一张模糊的小图。
   像素画问的是"这一格归哪一块"。
2. **放大必须 NEAREST**，不能用 LANCZOS/BILINEAR。

实测粒度（JK 立绘，源图 744×1754）：

| cell | 小图 | 观感 |
|---|---|---|
| 3 | 231×380 | 最细，几乎看不出像素格 |
| **4** | **173×285** | 精细与像素感的平衡点 |
| 6 | 115×190 | 精细像素 |
| 10 | 69×114 | 平衡 |
| 14 | 49×81 | 我的世界味最重 |
| 20 | 34×57 | 方块感强 |
| 28 | 24×40 | 最方块 |

# 路线 E：部件装配（高分辨率母版）

## 核心模型

**一个部件一块画布 —— 画完按自然尺寸摆进总图，最后合成一张图。**

```
眼睛：自己的画布 64×64（虹膜/瞳孔/两个高光/睫毛全在）
   ↓ 按**自然尺寸**摆进脸（不再受"成品占几格"约束）
脸：  自己的画布 200×240
   ↓ 摆进身体
身体：560×1300 总画布 —— 输出就是这一张
```

三条约束，缺一条就出问题（`assembly.py` 里都有 assert）：

| 约束 | 违反的后果 |
|---|---|
| 部件画布格数 = 成品格数 × **整数倍** | 非整数倍降采样会错位 |
| 装配偏移 = **整数格**（拼豆模式） | 半格错位，"眼睛歪了半格" |
| 降采样按格取**众数**，不插值 | 插值把拼豆糊成灰渐变 |

## 四条规则（和拼豆格阵相反）

| | 拼豆格阵 | **高分辨率母版** |
|---|---|---|
| 部件画布 | 成品格数 × 整数倍 | **按需给，用自然尺寸** |
| 摆放坐标 | 整数格偏移 | **头高为单位**（亚像素无所谓） |
| 降采样 | 按格取众数 | **不降采样**，保持原生分辨率 |
| 分隔手段 | 只能靠描边 | 明暗/描边都行，分辨率够就不缺内部格子 |

## ⚠️ 不要抗锯齿：保留硬像素锯齿

**实测：抗锯齿的平滑边不讨喜，带像素过渡的锯齿边才讨喜。**

```python
SS = 1                       # 不超采样
# PIL 的 ImageDraw 本来就不抗锯齿，所以 SS=1 直接就是硬边
im.resize(size, Image.NEAREST)   # 要放大只能用 NEAREST
# ✗ 绝对不要 LANCZOS / BILINEAR —— 会把硬边糊成灰渐变，像素感全丢
```

这一条同时解释了为什么**拼豆滤镜是最后的可选项而不是必须**：
母版本身就是硬边像素图，拼豆滤镜只是把像素**归并成更大的格**。

## 路线 F：加法 vs 减法（2026-10 新增）

上面那条是**减法**：高分辨率母版 → 归并成格。它的短板有三个：

| 短板 | 后果 |
|---|---|
| 细节不受控地丢 | 你没法决定哪条线该留、哪条该没 |
| 换一次格距结果就变 | 想做 3 个尺寸得分别试 |
| **控制不了用了哪些颜色** | 拼豆是**按颜色买豆子**的，这最要命 |

`bead_grow.py` 走**加法**：白画布 → 语义分区 → 每区上基色 → 逐层细分加变化。

```
L0   7x7    6 色     49 豆    纯色块（天空=蓝、太阳=橙红、山=绿、水=蓝）
L1  14x14  12 色    196 豆    天空起变化、山有结构、水有波纹
L2  28x28  17 色    784 豆
L3  56x56  20 色   3136 豆    云、光晕、山脊、水波
```

**它多给了三样东西：**

1. **每一层都是完整可用的一张图** —— 可以停在任意一层（L0 是 7×7 的小件，L3 是两块 29×29 板）
2. **每层的豆子清单** —— `#4876BE 658 颗`，直接照着买
3. **调色板纪律** —— 天空只从蓝系取色、山只从绿/灰取色，**永不串色**

三个坑（都踩过，自检里钉着）：

| 坑 | 症状 | 真因 |
|---|---|---|
| 归属用"覆盖率 > 0.5" | 山上出现**白洞**、水上方一条白带 | 区域交界处的细格两边都不满足 → 没归属 → 露背景。改成**按覆盖率取最大**，保证每格必有归属 |
| 每层各自 `_norm01(累加)` | 细节离散度**逐层下降**（0.200→0.128），加法语义丢失 | 逐层归一化把"多累加一个倍频程"的幅度增长抹平了。改成构造时按**全部倍频程之和**定一次标尺，各层共用 |
| 倍频程非零均值、未正交 | "加一层"反而方差**下降**（1.000→0.9385） | 粗网格双线性放大后本质是个双线性曲面（系统性倾斜），与更细的场相关 **-0.369**。零均值不够，必须 **Gram-Schmidt 正交化**；正交后 `Var(Σw·oct)=Σw²`，实测 1.0000→1.1180→1.1456→1.1524，与理论 `√1.25=1.1180` 吻合 |

> ⚠️ 这三条里有两条是"**测试写对了才发现**"的。第一版的测试是错的
> （拿 `cells.shape`（含 RGB 三通道）和 `(h,w)` 比、测"相邻格同色比例应该下降"
> 而它本来就该上升），改对之后立刻暴露了归一化和正交化两个真 bug。

## 路线 G：自适应四叉树（2026-10 新增）

路线 F 是**固定格数 + 均匀细分**：画布定死 W×H，第 L 层格子尺寸 = 2^(N-1-L)，
所有区域一视同仁。它有两个短板：

| 短板 | 后果 |
|---|---|
| 平坦区和高细节区用一样大的格子 | 要么平坦区浪费，要么细节区不够 |
| 画布必须能被 2 的幂整除 | 想做 384 宽得先算半天 |

路线 G 换成**按误差细分**：从"整幅一块"开始，对每块问一句
**"一个颜色能不能代表这块"** —— 能就留下，不能就切成四份，每份再问一遍。
切到误差够小、或到达深度上限、或切到单格。

```
maxd=2     16 块     三条大色带（天空 / 箭体 / 地面）
maxd=4    250 块     箭体、发射塔、发射台成形
maxd=6   2362 块     星点、钢架格网、蒸汽出现
maxd=8  11194 块
maxd=12 12336 块     终版，27 色
```

**细分深度是按内容自动决定的**（这是它相对固定层级唯一真正的优势）：

```
星点 8.5 ／ 钢架格网 8.2 ／ 探照灯 8.0 ／ 箭体 7.8 ／ 蒸汽 7.6 ／ 地面 6.2
```

星点和钢架格网是最高频的，切得最深；平坦的地面最浅。

四个坑（都踩过）：

| 坑 | 症状 | 真因 |
|---|---|---|
| **参考图不是"自己"** | 画面全乱、散着一堆灰斑 | 我让每个块去**别人的图**的对应像素位置取色。但那张图是动态姿势、我的分区是正面站立，位置根本不对应 —— "风衣区"取到的是背景。**"在原图基础上再细分"里的"原图"是「上一遍的自己」** |
| **把整块画成一颗豆** | 出来像贴瓷砖，不像拼豆 | 四叉树的块是平坦区的**压缩表示**，渲染时必须**展开成一颗颗豆**。一个 8×8 的块画成一个圆角矩形就毁了 |
| **`mask_circle` 在非正方画布上不是圆** | 脸被拉成竖长条 | 它用归一化坐标 `(x/W)²+(y/H)²≤r²`，112×192 上 r=0.14 给出 横15.7格 × 竖26.9格。**要圆就用 `mask_ellipse`（半径按格数）** |
| **大面积遮罩用最粗的倍频程** | 某区域分到 **0 格** | `oc[0]` 是 2×2 网格放大出的大尺度平滑场，`>阈值` 选中的是**一大片连续区域**而不是散布的团块；那片正好落在画布另一半，与位置约束没有交集。**要散布的团块就用 oc[2]/oc[3]** |

### 一个必须说清的概念

**自适应省的是"描述复杂度"（12336 块 vs 98304 格），不是物理豆数。**
块平铺整个画布，面积和恒等于画布。

所以"画布要多大有多大"是真的（切分支持奇数，不要求 2 的幂），
但**豆数仍然等于画布大小**。想少用豆子的话旋钮是**减小画布**，
让自适应把有限的格子花在细节上。

### 豆子渲染（`bead_style=True`）

`scale` = 每颗豆渲染成多少像素。`scale >= 8` 时每颗豆会画成
**圆角 + 左上高光 + 豆间细缝**，出图就是"拼豆作品"而不是"像素图"。

```
豆阵        豆数     平铺渲染   拼豆渲染
48x64      3072     0.00 秒    0.24 秒
96x128    12288     0.01 秒    0.34 秒
144x192   27648     0.02 秒    0.62 秒
```

**成本在逐颗画豆子，不在像素数** —— 27648 颗豆的拼豆渲染只要 0.62 秒。

## 镜像：**画左半，整体镜像一次**

⚠️ 这是本路线最容易翻车的地方，代价是**半格错位**。

**不要指望每个图元各自对称** —— `int(CX - 7)` 配 `int(CX + 7)` 在 `CX=31.5` 时
得到 15 列（中心在 31 而不是 31.5），整体偏半格。实测：裙子、鞋、领结、腰带**全中招**，
加了个"左右逐格相同"的断言才当场发现。

正解分两层：

```
第 1 层  对称部件（脸、领子、裙子、正面身体）→ 随便画 → mirror_left_to_right()
第 2 层  非对称件（发夹、侧马尾、挎包、姿势）→ 镜像**之后**才画
```

镜像公式：中轴在格线 `A = cw // 2` 上时，格 `i` 的镜像是 **`cw - 1 - i`**
（不是 `2*A - i`，那是"以格心为轴"，会整体错半格）。

## 分辨率守恒（必须先想清楚）

**画布画得再大，成品精度仍由"它在成品里占几格/几像素"决定。**
画大只买到两样东西：**手好画、比例准**。买不到更多成品细节。

实测：一个在 32×32 画布上画得有虹膜+瞳孔+两个高光的眼睛，
**降到成品 4×4 格后只剩一个蓝方块**。所以部件里任何特征的宽度
必须 ≥ 成品 1 格，否则降采样时直接消失。

## 两套比例，别混

**MC 玩家模型是 4 头身，不是 7 头身**（腿 12 + 身 12 + 头 8 = 32px，头占 8 → 4.0）。
"7 头身 + MC 体型"必须把两件事拆开：

| | 保留 | 换掉 |
|---|---|---|
| MC 味 | **方盒构造**（轴对齐、零曲线）、宽度方案（身宽 = 1 头宽） | 纵向比例（4 头 → 7 头） |
| 日漫味 | 锥形躯干 + 胶囊四肢 | 方盒构造 |

⚠️ **直接套 MC 宽度到 7 头身会变成竹竿**：MC 肩宽/身高 = 2H/4H = 0.50（敦实），
7 头身 = 2H/7H = 0.286（瘦长）。**MC 的敦实感来自"头占身高 1/4"，不是来自方盒。**
要敦实就用 4~5 头身；要日漫身段就接受瘦长轮廓。

## 头高 → 脸精度的实测对照

| 头 | 画布 | 脸能画到什么 |
|---|---|---|
| 8 格 / 16px | 48×128 | 两个色块当眼睛 + 一条嘴，只能"是张脸" |
| 12 格 / 24px | 64×184 | 眼睛带高光、嘴、腮红，角色间差别很小 |
| **16 格 / 32px** | **80×240** | **瞳孔+高光、眉毛、嘴、腮红 —— 甜点** |
| 20 格 / 40px | 96×296 | 再多发丝、鼻影 |

# 平面图木偶（`puppet.py`）：能做什么、**做不到什么**

给一张**任何**平面图做小幅动态。两件事：

| 做法 | 干什么 | 靠什么成立 |
|---|---|---|
| **局部平滑变形** | 让某一块（手掌、头发、衣摆）柔和地动 | 连续映射，**永不产生洞** |
| **局部贴片** | 眨眼、张嘴这类局部替换 | 盖住的地方**本来就有确定的颜色** |

```python
import puppet as PP
mask = PP.blob_mask(img.shape[:2], (300, 232), rx=134, ry=127)   # 可动区域
dx, dy = PP.rotate_field(img.shape[:2], pivot=(332, 322), angle_deg=12,
                         center=(300, 232), rx=143, ry=138)
frame = PP.local_warp(img, dx, dy, mask)        # 区域外**逐字节不变**
frame = PP.blink(frame, (447, 174, 503, 269))   # 眨眼
```

## 能力边界（硬边界，不是调参能解决的）

**分界线是一句话：移开一块像素之后，底下有没有东西填。**

| 动作 | 单层图 | 为什么 |
|---|---|---|
| 局部摆动 / 呼吸 / 头发飘 | ✅ | 连续变形，不产生洞 |
| 眨眼 / 张嘴 / 表情 | ✅ | 局部且位置固定，盖住的地方颜色确定 |
| **抬手 / 转身 / 换姿势** | ❌ **不可能** | 手臂盖住的**身体和背景像素原图里从来没有**，移开就是一个洞 |

**要让肢体动起来只有两条路，都不是"再调调参数"：**

1. **输入换成分层文件**（PSD / 分开的 PNG）—— 每层独立变换。Live2D 就是这么做的
2. **有生成式补图**（inpaint）—— 把露出来的洞生成出来

⚠️ 实测（抬臂比 V 的姿势）：**手臂和飘起的外套是同一种白色、袖子盖在手臂上 ——
连"手臂"这个部件都切不出来。** 所以只能做"掌部小幅摆动"，做不了"真的转肩肘"。
换任何一张**单层**图结果都一样 —— 这条限制与图无关，与**单层**有关。

## 两个已踩的坑

- **变形区域外必须归零。** 位移场全局施加时，即使衰减到 0，浮点重采样也会轻微改动全图，
  看起来就是"全身都在扭"。必须用 `local_warp` 只替换区域内像素，并用断言验证
  **区域外最大像素差 == 0**。
  （断言也要写对：`允许改动区域` 必须把手 ∪ 眼睛都算进去，否则眨眼会被误报成渗漏。）
- **眨眼填充要夹在肤色窄范围内。** 迭代插值仍会从边界带进睫毛/头发的暗色，
  不夹就会在眼窝留一块暗晕。按眼周亮色像素的中位数夹 `[-15,+12]` 解决。

# 共用原理：色块 → 像素细化

## 阶段一：色块（`mesh.render_regions`）

把每个区单独渲成一张掩膜 → 高斯模糊 → 陡峭 smoothstep 重新二值化。
边界因此落在**平滑曲线**上，不再沿三角面走。

```python
im = mesh.render_regions(V, F, size, face_rgb,     # 相同颜色的面自动归成一个区
                         shade=False,              # 纯二维：每区一块纯色
                         smooth=3.0,               # 掩膜平滑半径（锯齿幅度的一半左右）
                         edge=3.0,                 # 越大边界越硬；太小会糊
                         outline=None, fixed=TF)
img, masks = mesh.render_regions(..., return_mask=True)   # masks: {颜色: 浮点掩膜}
```

`return_mask` 可以把一次渲染拆成两层（前后发就是这么劈的：渲两个标记色，
拿掩膜按 `back_m >= front_m` 分给两层）。

## 日漫式平涂阴影（`cel` / `cel_thr`）

纯平面（`shade=False`）会**把鼻梁和嘴唇一起抹掉** —— 那两样原来是靠明暗透出来的。
但直接开 `ambient` 平滑光照又变成"立体感"，不是日漫那种平涂。

正解是 `cel`：**只有亮/暗两档**，交界由 `N·L` 的符号定，得到的是**一块阴影形状**：

```python
mesh.render_regions(..., cel=0.76, cel_thr=0.08, two_sided=False,
                    light=(-0.35, 0.50, 0.79),      # 左上前方
                    shadow_smooth=1.0, shadow_edge=4.0)
```

| 参数 | 含义 | 实测取值 |
|---|---|---|
| `cel` | 暗面亮度系数（亮面恒 1.0） | 皮肤 0.76（暗 24%）、头发 0.86 |
| `cel_thr` | `N·L` 低于它才算暗面 | 0.08。**0 太大**（半球都算，鼻侧糊成一条）；**0.22 太小**（鼻子和嘴的阴影直接没了） |
| `shadow_smooth` | 阴影形状在 2D 上的平滑半径 | 1.0。**2.2 会把鼻子那块几像素的阴影抹掉** |
| `shadow_edge` | 重二值化的陡度 | 4.0 |

**⚠️ 别用 `ambient` + `bands` 分段量化做平涂阴影**：
`floor(inten*bands)/(bands-1)` 只在 `inten` 铺满 0..1 时才分得出档。
`ambient=0.8` 时 `inten∈[0.8,1]` → 全部塌到 1，**阴影根本不出现**。

**⚠️ `two_sided=False` 要配"法线先翻到朝相机"才成立**（代码里已这么处理）：
翻完再取 `max(0, n·L)`，背光就是暗面。**不要**走背面剔除 —— 素体绕序不一致
（剔了头上开洞）、头发的后发是背向壳（剔了变空心圈）。

## 阶段二：像素细化（`pixel.py`）

色块只能给"大致"的形状。鼻梁、嘴唇、下颌线、腿间缝这些**在分区里根本不存在**，
必须用像素级操作补。**全部操作写成 ops（JSON 列表）**，可重放、可只调一步。

| op | 用途 |
|---|---|
| `set` / `line` / `path` | Bresenham + 方块笔刷，**不做抗锯齿**，`w=1` 就是一个像素宽 |
| `flood` | 有界填充：从某点出发把相近颜色的连通块刷成新色（"这一块要蓝色"） |
| `shade` | 多边形内压暗。**用 `to`（填固定色）不要用 `scale`（乘系数）** |
| `cast` | 2D 投影阴影：把遮挡物色块沿屏幕方向平移，落在目标色上的部分压暗 |
| `seam` | 取两块颜色之间的交界线掩膜 |
| `smooth` | 把某个纯色块的边界在 2D 上重新平滑 |
| `outline` | 整图描边 |

```python
import pixel as PX
ops = [
    {'op': 'path',  'pts': [[x,y],...], 'color': INK, 'w': 1},
    {'op': 'flood', 'pt': [x,y], 'color': BLUE, 'tol': 12, 'grow': 1},
    {'op': 'shade', 'poly': [[x,y],...], 'to': [186,172,165], 'on': [SKIN]},
    {'op': 'cast',  'from': HAIR, 'dx': 7, 'dy': 12, 'scale': 0.87, 'on': [SKIN]},
]
PX.save(PX.apply_ops(PX.load(src), ops, verbose=True), dst)
```

### 投影阴影（`cast`）

法线光照**算不出**刘海投在额头上的那块暗部 —— 额头本身朝前、明明受光。
这类阴影是"遮挡物投下来的"，用 2D 投影更对。
把遮挡物色块沿屏幕方向分步平移累积，落在 `on` 指定颜色上的部分压暗。
光在左上前方 → 阴影落向右下（`dx>0, dy>0`）。

### 投影多边形阴影（`shade`）

形状由**三维几何**算好后填一块平涂阴影 —— **下颌投在脖子上的那块**：
把下颌弧（分区 `t=0.867` 那圈朝前的顶点按 x 分箱取最低点）整体下移 `DROP` 像素，
两条边合起来就是投影多边形。实测脖子总高约 71px，`DROP=28` 覆盖上 40%。

**⚠️ 用 `to`（填成固定色）而不是 `scale`（乘系数）**：一块阴影区域里往往同时有
"底色"和"已经被 cel 压暗过的色"，同一个系数乘上去会出**两档深浅**，
看着像在脖子上打了块补丁。

### 上眼睑线

压平 + 只有阴影的话，眼睛只是一块暗斑。**日漫最强的脸部件是上眼睑那条粗线** ——
沿眼球组件上缘画一条两端下收的弧（`w=2`），眼睛立刻立住。这条线比鼻子和嘴都重要。

# 踩过的坑（全表，都别重来）

## 结构与颜色

| 坑 | 症状 | 正解 |
|---|---|---|
| **`cv2.kmeans` 没设随机种子** | **同一张图、同一组参数，每次跑出来的块数都不一样**（实测 475 / 464 / 453，顶点 4391 / 4460 / 4371）。文档里的对照表全部浮动，"同参数逐字节一致"这条验收根本不成立 | `cv2.setRNGSeed(seed)` 放在 kmeans **之前**（`KMEANS_SEED=20260928`）。注意 `KMEANS_PP_CENTERS` **救不了** —— 它只是初始化得更聪明，仍然随机，OpenCV 默认拿时钟当种子 |
| **只用外轮廓** | 环形区域（包住脸的头发）被填成实心块，**五官整个被盖掉**，误差 5.11 | 用 `RETR_CCOMP` 取外轮廓 + **内孔**，逐个挖掉 → 误差 3.86 |
| **`int16` 平方溢出** | 最近色算错，量化误差假性飙到 201/255 | 距离计算用 `int32`（255²=65025 > int16 上限） |
| 用 `MORPH_OPEN` 去噪 | 眼线、嘴线这种 1~2px 的细节被整个抹掉 | 用 `medianBlur` |
| 明暗用**交集** | 大区域上交集≈整个区域 → "整体压暗"而不是打光 | 用**差集**：`mask & ~shift(mask, 光照方向*band)` |
| 色带取 1px | 完全看不出明暗 | 像素/平面风是**硬边色带**，band 给到 5~8px |
| 镜像取列取反 | "对称化"之后左右差异反而从 2.5 涨到 61.6 | 保留左侧时取 `mir[:, :W-x]`（**前** W-x 列） |
| **对不对称的图强行镜像** | 侧身动态姿势被镜像成万花筒（残差 24.73） | `mirror_half` 默认**拒绝**：残差 > `SYM_MAX_ERR`(12.0) 就报错 |
| 模块命名成 `struct.py` | **遮蔽标准库 `struct`**，cv2/PIL/numpy 内部全炸 | 命名避开标准库（所以叫 `shapes.py`） |

## 渲染

| 现象 | 真因 |
|---|---|
| **整张图纯黑** | `g = num/den` 相除后**已经是 0..1**，又除了一次 255 → 亮度只剩 0.0035，取整归零 |
| **满脸碎斑** | `split_by_depth` 返回的是**面数组 (M,3)** 不是索引；拿它 `lbl[fb]=...` 成了花式索引 |
| **脸上一块块深灰** | 素体自带头发壳（独立壳，垂到肩）。光改颜色不够，它的背光面会渲成深灰压在脸上 —— 要**整块丢掉** |
| 头发斑驳 | `abs(n@L)` 是双面片的 hack，法线一垂直于光就暗。闭合壳本应剔背面改用 `max(0,n·L)`；但素体绕序不一致、后发是背向壳，所以立绘仍用 `abs()` + 正面光 + 加大 `shade_smooth` |
| **层与层之间一道接缝** | 描边**整图只描一次**。逐层描边会把层边界描出来 |
| **两脚之间一个黑方块** | 网格里有片几何和身体不连通；描边宽度比它还大就被填成实心块 → `mesh.drop_specks()` |
| **左右一边露一边秃** | 前/后发分界取"头中心深度"，阈值正好落在头发两侧 → 左右被分进不同层。改成取**脸的前表面**（z 分位 85%） |
| **组件渲染成一大团** | `project` 会把传进来的顶点**自动缩放填满画布**。组件必须和身体共用同一套变换：`fixed=TF` |

## 像素画

| 现象 | 真因 |
|---|---|
| 腿间缝看不见 | 1 像素宽的缝在 cell=10 的一格里被"每格取众数"吃掉。线宽要按 `cell/2` 画 |
| **头顶两根悬空横杠** | `np.roll` 会**环绕**：底部前景被滚到顶部，顶边被误判成轮廓。用不环绕的平移 |
| 两腿之间拖出一条悬空墨线 | 腿分开的地方**本来就是背景**，不该再画中缝。只有两腿贴着才画 |
| 白衬衫看不见 | 衬衫 (242,242,246) 和背景 (250,250,252) **距离只有 26**，几乎同色。纯色块管线里特别容易踩 |

## 定位与锚点

| 现象 | 真因 |
|---|---|
| **眼睛画到头发上、领子横在胸口** | 靠"皮肤色块在哪"定位是错的 —— 量化会把头部正面的皮肤并到另一档，只匹配到侧脸。**所有锚点用几何算** |
| 脸底取到脚底 | "中间列皮肤的最下行"当脸底是错的 —— **腿也是皮肤色**。要取"从头顶往下第一段连续皮肤" |
| 领子/裙子画成空心轮廓 | 每行只写了左右各两格。要**填满整行** |
| 脖子怎么调都粗 | 判据 `w < 0.050` 的半宽 = 总宽 0.10 身高 ≈ 1 个头宽 —— 那切出来是**肩**。脖子必须由解剖宽度定义（`W_NECK=0.035`） |
| 腿粗 2 倍调不动 | MakeHuman 的 `l/r-upperleg-scale-horiz-decr` 等 6 组目标在这个基础网格上**完全不生效**（`apply_targets` 静默跳过，量出来一模一样）。直接改几何 |
| 只收半宽没用 | 腿并拢时整块宽度主要是**两条腿轴线的间距**贡献的。要连轴线一起往中轴收（`k_center`） |
| 人物被压成细条 | canon 的半宽是**相对身高**的比例，漏乘身高 |

## 部件装配

| 现象 | 真因 |
|---|---|
| **左右差半格，断言当场报出来** | 逐图元各自对称是**做不到**的：`int(CX-7)` 配 `int(CX+7)`，`CX=31.5` → 15 列，中心在 31。裙子/鞋/领结/腰带全中招。**正解：画左半 + 整体镜像一次** |
| 镜像后角色变对称了，发夹没了 | 非对称件必须画在**镜像之后**（第 2 层） |
| 镜像完又变不对称 | 把只画在左半的装饰留在了镜像之后。要么挪到镜像之前，要么单独 `mirror_cols` |
| `cell=3` 时格子铺不满画布 | 画布宽 128 / 3 = 42.67。**cell 必须整除画布两边**（128 = 2⁷ → cell ∈ {1,2,4,8}） |
| 中轴不在格线上 | **列数必须偶数**，中轴才落在格线 `A = cw//2` 上 |
| 头是奇数格 → 脸画不对称 | 头 22px / 格 2px = **11 格**是奇数，左右各 5.5 格。头高必须量化成**偶数格**（12 格 = 24px） |
| **低分辨率下全局描边把脸糊掉** | 描边按颜色差找边界 → 眼/嘴/腮红一起被描黑。**否定结果**：调色差（看不出）、k=0.52（糊）、k=0.72（脏）**四轮全失败**。真因是那个尺度下几乎每格都紧邻异色格，**没有"内部格子"可供描边**，等于整体压暗 |
| 描边描出一圈脏边（第二次） | 顺序错了。**必须先描边，再画脸部细节**，让细节落在描边之上 |
| 两条同色腿糊成一块 | 平面渲染没有立体阴影来分隔。要么画 1 格分隔缝，要么靠**明度差 ≥ 30**，要么干脆走高分辨率母版（立体/明暗自然分开） |
| 白袖子配白上衣看不见 | 同上 —— 同色/近色相邻部件在低分辨率下必然合并 |
| 画得再细，成品还是糊 | **分辨率守恒**：一个 32×32 画的眼睛降到成品 4×4 只剩一个蓝方块 |
| 放大后像素感全丢 | 用了 LANCZOS/BILINEAR。**只能用 NEAREST** |
| 图画到一半 slice 崩（`TypeError: slice indices`） | 行表里混进了浮点（`5.5 * HC`）。而且**画布高必须 ≥ 头身比 × 头格数** —— 78 格装 7×12=84 的头身比，头顶算到行 −9 |
| 以为 MC 是 7 头身 | **MC 玩家模型是 4 头身**（腿12+身12+头8=32，头占 8）。而且**把 MC 宽度套到 7 头身会变竹竿**：肩/高从 0.50 掉到 0.286 |

## 必须知道的限制

**1. 路线 A 是"描"，不是"画"。** 提取出来的结构是参考图的衍生品。
当**结构素材**用没问题（改轮廓 + 换配色 = 新设计），但直接当原创作品发布有问题 ——
尤其参考图本身来自别处时（注意图上的"AI生成"水印之类）。
**要用在正式项目里，请先把轮廓改到位**，再用 `art.py edit` / `paste` 定稿。

**2. 路线 A 的 94% 不是 100%。** 锯齿和碎块来自画家算法的层序 + 简化容差。

**3. 不能凭空"想"出角色。** 路线 B/C 能生成角色，但都是在**已有几何**上做的
（MakeHuman 网格 / canon 方块）—— 角色长什么样由体型配方、服装参数、像素 ops 决定，
不是模型想出来的。真·文生图需要扩散模型那一层，本技能不提供。

**4. 适合的风格**：平面着色 / 低多边形 / 像素风 / MC 方块风 / 矢量扁平风。
写实插画（有体积、有布料褶皱、有发丝）超出这套方法的能力。

**5. 对称化只适合正视图。** `mirror` 会先测左右镜像残差，超过 12/255 直接拒绝。

**6. 描边会显著改善观感。** 同一个结构，`outline=3` 比 `outline=0`
"像插画"的程度差很多 —— 线稿感主要来自这一层。

bead_grow.py        **从白画布"加"出图来**（与"母版降采样"的减法路线相反）

                      它在非正方画布上会把圆拉成椭圆）
                    · scale / bead_style：每颗豆渲染成多少像素、要不要画成真拼豆
                    · 提示词机制：先划语义区域（矩形/圆/多边形/曲线下方）

bead_from_ref.py    参考图驱动：按颜色把人设各元素分出来 + 位置先验 + 每区独立调色板
                    ⚠️ 只在"背景与主体颜色差得够远"时可用（见 SKILL.md 的坑表）
bead_quad.py        **自适应四叉树**：从整幅一块开始，一个颜色代表不了就切四份

                    · render(scale, bead_style)：把块**展开成一颗颗豆**再画

selftest.py    自检（自己造测试图，不依赖外部素材）

`shapes.py` 里所有"编辑"都走同一条路：**栅格化 → 改像素 → 重新提取结构**。
比直接改多边形表稳（不用处理多边形自交、内孔失效这些麻烦事）。

`parts.py` / `figure.py` / `build_char.py` 的 `__main__` 是**演示脚本**，
会往 `LAYERED_ART_OUT`（默认系统临时目录）写中间图。当库用就直接 `import`。
